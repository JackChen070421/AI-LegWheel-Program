## 2. 为什么现在要解决

- 云台板尚未做出，当前 `BOARD_COMM_GIMBAL_PRESENT=0`，接收“只存不消费”；一旦接上，控制权仲裁/超时/急停必须明确；
- 线上编码与本地 `RobotStatus` 编号不同，混用会切错状态；
- 急停是安全功能，注释与实现不一致是高风险。

## 3. 目前已知（证据）

### CAN 帧（`board_comm.h`）

| ID | 方向 | 内容 |
|---|---|---|
| `0x10F` | 云台→底盘 | yaw 速度指令 / 自瞄标志 / 请求状态 / 目标腿长 |
| `0x11F` | 底盘→云台 | 血量 / 弹速 / 颜色 / 比赛开始 |
| `0x12F` | 云台→底盘 | yaw 力矩 / yaw 目标角速度 |
| `0x14F` | 底盘→云台 | yaw 电机实际角度 |
| `0x13F` / `0x22F` / `0x15F` | 暂未接入 | IMU/键鼠/目标角度 |

### 状态编号

| 状态 | 线上编码 | 本地 `RobotStatus` |
|---|---:|---:|
| RECOVER | 0 | 2 |
| NORMAL | 1 | 1 |
| STEP_UP | 2 | 6 |
| JUMP | 3 | 3 |
| SPIN | 4 | 7 |
| ESTOP | 5 | 5 |

> 云台请求底盘状态时必须显式映射，不能直接混用（`board_comm.h` 注释已警告）。

### 急停

- 注释写“分级阻尼”，实现看起来是零力矩（t1 抽查，未逐行确认）；
- 需要明确“安全优先”的预期：零力矩会让车自由倒下；阻尼/支撑可能更安全但发热。

## 4. 可选方案

| 议题 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 协议 | 按现有代码冻结 v0.1，补文档 | 重新设计（考虑带宽/扩展） | 先冻结、后迭代 |
