# Agent 执行规范（防卡死 / 防截断 / 可交接）v0.1

> 日期：2026-10-19  
> 适用范围：本项目所有 AgentTeams 成员、subagent、Captain 自执行任务。  
> 背景：t3 审阅发现，t1/t2 的任务输出在 §2 之后被 `[truncated]`，导致监管者无法审阅构建/清理/资料段；另外长文件通读会迅速耗尽上下文。本规范用于杜绝“长时间空转、反复读同一文件、输出被截断、结论不可追溯”。

---

## 1. 时间盒（硬约束）

| 任务类型 | 时间盒 | 检查点 | 超时动作 |
|---|---:|---|---|
| 侦察/盘点 | 20 min | 每完成 1 个小节写 1–3 行小结 | 立即停止，提交已完成部分 + 卡点 |
| 写作/文档 | 30 min | 每写完 1 个文件/章节 | 停止扩写，先交付可用版本 |
| 审阅 | 12 min | 每审完 1 个维度 | 提交已审部分；未审项标“未覆盖” |
| 迁移/清理 | 30 min | 每完成 1 类文件 | 回滚当前类，报告 |

规则：
- 时间盒是 **墙钟上限**，不是目标；提前完成就提前交。
- 到达 80% 时间仍未产出可交付内容 → 停止阅读，先写“已知/未知/下一步”。
- 禁止“再多读一点就明白了”的开放式探索。

## 2. 大文件读取规则

| 文件 | 规则 |
|---|---|
| `Chassis.cpp`（245 KB / 5,523 行） | 先 `grep` 函数/宏/状态；只读命中段 ±30 行；禁止全文通读 |
| HTML（上交 WBR_*.html，1.1 MB，含 base64 图片） | 先剥标签抽正文；跳过 `data:image`；公式看 `texencoding` 属性 |
| 参考源码（山海 8.7 MB） | 只读目录结构 + 3–5 个关键文件；禁止通读 `Library/` |
| PDF（3.8 MB） | 先抽文本/目录；只读相关章节；扫描件/图片标注“不可读” |
| `.slx` / `.mat` | 不直接读；记录路径，必要时请用户导出 |
| 二进制/3D/视频 | 只索引，不读取 |

通用阈值：
- >50 KB：先 `grep`/摘要，再定点读；
- >200 KB：禁止全文读取；
- 同一文件最多读 2 次（第 3 次必须先说明为什么前两次不够）。

## 3. 输出与交接（解决截断）

1. **>60 行或含表格的产出必须落文件**（`docs/` 或任务指定路径），消息里只放 ≤15 行摘要 + 文件路径。
2. 任务输出字段只放：结论、证据（`path:line`）、未决问题、产物路径。
3. 禁止把关键结论只放在聊天消息里；聊天消息视为“通知”，文件才是交付物。
4. 交接格式固定：

```text
状态：完成 / 部分完成 / 阻塞
产物：<path>（没有则写“无”）
结论：3–5 条
证据：path:line / 实测命令
未决：编号（对应 open-questions）
下一步：1 条
```

## 4. 卡死判定与上报

出现任一情况，立即停止并上报，不重试第三次：
- 连续 8 分钟没有新增证据或产出；
- 同一命令/同一文件重复 2 次仍无进展；
- 上下文接近上限（>70%）；
- 输出开始循环、重复、或不断自我修正；
- 依赖的外部条件缺失（文件不存在、工具不可用、需要用户数据）。

上报模板：
```text
BLOCKED: <一句话>
已完成：<产物/结论>
卡点：<缺什么/哪个命令失败/原错误>
已尝试：<1–3 条>
需要：<用户回答 / 授权 / 换工具>
```

## 5. 提示词模板

### 侦察
```text
目标：<一句话>
输入：<文件清单，按优先级>
输出：<≤N 行，固定小节>
时间盒：<N> 分钟；到点即停
纪律：先 grep 再定点读；不编造；不确定标 TBD；只读
```

### 写作
```text
读者：<人/agent>
输入：<侦察产物/参数/证据>
结构：<章节>
约束：中文；每个数值给来源；≤N 行；不复制长表
验收：<3 条可检查标准>
```

### 审阅
```text
对象：<文件/任务输出>
检查：覆盖度 / 矛盾 / 未证实结论 / 链接 / 是否符合 open-questions
输出：pass 或 findings（id/severity/problem/requiredFix）
限制：只抽查关键证据；12 分钟
```

## 6. 监管者（Supervisor）职责与边界

职责：
- 维护本规范与提示词模板；
- 审阅成员产出：覆盖度、矛盾、未证实结论、是否跑题；
- 对“太慢/太散”的任务给出更窄的提示词建议；
- 维护问题清单的覆盖度，防止漏问；
- 在交付前做一次独立抽查（至少 5 个 `path:line`）。

边界（如实说明）：
- AgentTeams 成员**看不到彼此的实时状态**；Supervisor 只能审“已交回”的产出，不能实时中断别人。
- **实时中断由 Captain 执行**：Captain 看 `agent_teams_status`，超时则发窄指令、重派或接手。
- Supervisor 不改任务契约、不直接改代码/文件（除非任务明确授权）。

## 7. 禁止事项

- 编造参数、结论、测试结果；用“应该是/大概”代替证据。
- 未备份/未确认就移动、删除、重命名文件。
- 修改 `researchs/`（只读参考）。
- 修改工作区外文件；未获逐次授权就 push/PR/合并远端（默认不直推 `main`，见 `shortcut.md`）；安装软件（除非用户明确授权）。
- 直接修改 `main` 或强推共享分支：按 `shortcut.md` §3 的红线，先权限确认 + 用户明确确认，默认走分支 + PR。
- 把 245 KB 源码、1.1 MB HTML、8.7 MB 参考库整篇塞进上下文。
- 在任务输出里放超长内容导致截断。

## 8. 质量门（文档类）

- 每个数值/结论有来源：`path:line`、实测记录、或用户口述+日期。
- 每个 `TBD` 能对应到 `open-questions.md` 的编号。
- 相对链接可点；坏链在交付前修掉或标注。
- 单文档正文 ≤300 行（提案/ADR/附录/证据索引不计）；超过则拆分。
- 交付前由非作者做一次抽查（≥5 条证据）。

---

## 9. 本次教训（2026-10-19）

1. t1/t2 的任务输出在 §2 后被截断，监管者无法审后半段 → **长产出必须落文件**。
2. 大文件通读会挤掉后续推理空间 → **grep-first + 定点读**。
3. 没有版本控制时，“先改再说”不可接受 → **S0 基线优先**。
4. 结论必须带 `path:line`，否则下一轮无法复核 → **证据随结论走**。
